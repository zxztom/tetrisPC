# 连续 PC 实验室

在项目中的 TETR.IO 桌面客户端内自动执行 **七次纯四行 PC（70 块 / 十袋）**，或 **四行 PC → 四行 PC → 六行 DPC（35 块 / 五袋）**。程序读取窗口截图，识别当前块、Hold、Next 和棋盘，发送游戏按键，按所选档位核对动作或落地结果。

## 随机来块，直接开始

双击 **`开始随机PC.cmd`**。如果游戏未打开，它会打开项目中的 TETR.IO.exe；进入单人七袋练习，空棋盘且游戏窗口在前台时，程序自动接管。支持当前 ZEN 的五个 Next、自然下落；高速重力与 20G 尚未验证。不需要设置、填写或匹配种子。

客户端已经打开随机七袋开关。机器人只从窗口读取当前块、Hold、实际显示的 Next 和棋盘；七袋规则能唯一确定的块可以推断，其他未来块仅作为可能情况参与规划，每次落地后重新核对实际画面。

也可以双击 **`启动PC实验室.cmd`**，点击“开始随机 PC”。默认等待新局，不会清掉你已经玩了一半的棋盘；勾选“开始前重开当前练习”才会重开当前局。当前没有从任意中途堆积恢复 PC 的功能。

| 已配置的练习参数 | 值 |
|---|---|
| 模式 | SOLO → CUSTOM，无垃圾 |
| 随机方式 / use random seed | 7-BAG / ON |
| 重力 / use levelling | 0 / OFF |
| kick table | SRS+（网页可明确选择标准 SRS） |
| Next | 五个（按实际显示数量识别） |
| lock delay | 600 |
| 结束目标 | LINES，150；一轮七次 PC 共 28 行 |
| 按键 | ← / → 移动，↑ 顺时针，Ctrl 逆时针，Shift Hold，空格硬降 |

**F8 或 Esc 停止；切换到其他窗口也会停止。** 网页中的“停止”按钮取消任务；`停止PC实验室.cmd` 取消任务并退出本机服务。

连续循环次数 0 表示持续执行。勾选“PC 无法继续时清空 / 重开并持续尝试”，恢复次数设为 0，可不限次数重试。ZEN 使用配置里的重试键清棋盘，保留等级与累计进度；CUSTOM 重开随机局。每次恢复都记录为断链，前后成绩分开。画面不一致、意外横移或失去焦点仍然停止。恢复选项默认关闭，可保存并供快捷启动器沿用。

## 操作配置与重力

TETR.IO 的 **CONFIG → EXPORT SETTINGS** 导出的是 JSON 格式 `.TTC`。在网页选择此文件后，程序读取 GUIDELINE / WASD / CUSTOM 的实际键盘绑定，以及 ARR、DAS、DCD、SDF。游戏里改了设置，需要重新导出并载入；程序不声称能直接读取游戏内存中的设置。

“生成所选速度的游戏配置”保留原按键及声音偏好，修改 ARR=0、DCD=0、SDF=∞；稳定 / 快速 / 冲刺分别推荐 DAS=6 / 4 / 2F。快速和冲刺选择轻量图形，并关闭遮挡棋盘的特效。下载后拖进 TETR.IO 导入，再点“已导入游戏，应用此配置”。原设置备份在 `output/user-original-20261014.ttc`，本次生成文件为 `output/pc-fast.ttc`，程序当前使用 `output/current-config.ttc`。CLI 支持 `--config 路径`。

有重力时，根据每次截图中的四格位置恢复实际高度与旋转，重新求可达路线；核对动作时允许合法的自然下降，硬降前检查投影。观测到下落后缩短搜索预算，给移动留时间。ARR=0 时，合法的连续贴墙移动改为按住一次；软降瞬降只用于必须旋入的落点。输入间隔可以单独调整，识别与求解也占时间。冲刺的空中路线在落地后核对整盘，低处动作和旋入仍先核对投影。

本次实机在 **ZEN、STATIC 0.02、有限锁定延迟、五个 Next、随机七袋** 下连续完成两次四行 PC：20 块、8 行、没有重试。记录在 `output/live-20261014-100459-1eb97707/session.json`；包含每步实际观测高度、贴墙操作及瞬降旋入组合。另一次实机连续运行遇到两次 PC 断链，均清棋盘后自动继续完成 PC；等级与累计分数保留。高速重力、垃圾模式和 20G 仍未验证。

## 速度档位

网页可选择逐键核对、稳定（目标 2 PPS）、快速（目标 4 PPS）、冲刺（目标 6 PPS）及自定义。档位会保存，快捷启动器沿用；实际速度包含求解与画面核对。CLI 例如 `--speed sprint`，可附加 `--interval-ms`。

本机 ZEN / SUBZERO、随机七袋、五个 Next、SRS+、MINIMAL 图形下，连续 **70 块、七次四行 PC、28 行** 实测 **6.008 PPS / 11.651 秒**；未重开、未读取种子、没有漏键补正。另一轮同样完成 70 块，平均 5.807 PPS。稳定档位两次 PC / 20 块实测 2.010 PPS。记录和逐块独立回放见 `output/speed-verification.json`。

已修复快速组合错误提示中的两种情况：PC 动画遮挡等待稳定画面；重力自然锁定并推进 Next 记为断链，按照恢复选项清场重试。仍可定位的漏键从当前位置补正，完整分辨率读取作为高速识别的回退。高重力与 20G 速度没有用上述零重力记录代替验证。详见[速度档位与六块每秒实测](docs/速度档位与六块每秒实测.md)。

## 七次纯四行 PC

正常启动器现默认纯四行模式。网页“连续 PC 方式”可切换纯四行与 4＋4＋6，“游戏旋转表”需与 CUSTOM 配置一致，默认 SRS+；ZEN 始终使用 SRS+。

[七次四行 PC 方法说明](docs/七次四行PC循环说明.md)与[本次实机 70 块交互图解](docs/七次四行PC实机图解.html)解释七阶段来源分组、四块骨架、有限预览收尾和十袋校验。服务页面为 http://127.0.0.1:8787/pure4-manual 。

2026-10-14 实机完成 **70 块、七次四行 PC、28 行、一轮**；五个 Next、随机七袋、SRS+、零重力。前四块后因 O 预览重复识别暂停，修复后从原棋盘继续；同一局未重开，未读取或填写种子。完整记录 output/live-20261014-080335-f64062fe/session.json；独立回放 314 个实际动作及十袋来源校验见 output/pure4-native-verification.json。这证明该次完成，不代表任意随机序列无限不断链。

算法接入 knewjade 的公开 Best Chance Field：1,038 个七阶段四块地形通过导入检查，按实际可用块、阶段、Hold 和镜像筛选，再验证 SRS/SRS+ 可达路径。数据原始百分比只用于排序，不是本机成功率。保留无合适结构时的有限预览搜索。

另外修复日落背景误认出生 Z、黄色 O 边缘被重复识别的问题；互斥锁防止两个入口同时发送游戏按键。图解中的中间路线与本次实机动作一致。

## 人类操作说明与旋转修复

[不知道种子的连续 PC 说明](docs/不知道种子的连续PC说明.md)解释袋成员计数、Hold、有限 Next 决策和 4＋4＋6 分段。[交互图解](docs/不知道种子的连续PC图解.html)含一轮真实随机 ZEN 的 35 块：每步显示当前块、Hold、五个 Next、落点、动作演示和消行结果。服务启动后也可打开 http://127.0.0.1:8787/manual 。

图解的落点已在历史实机记录核对；新版优先空中旋转路线在这些落点上离线验证了 153 个动作，没有重新在实机执行整轮新版按键。第 10、20、35 块全清及五袋来源校验均通过。具体块序是案例，任意随机局需要根据自己的 Next 重新选分支。

你报告的 I 在 Z 上方跑偏，来自 ZEN SRS+ 的 I 踢墙尝试顺序与旧标准 SRS 预测不同。[规则核查](docs/TETR.IO规则核查与旋转策略.md)记录来源与实际验证范围。当前实机已经验证“出生处逆时针 → 左四次 → 硬降”准确落在最左列，记录见 output/native-i-left-verification.json；没有清除或重开 ZEN 进度。

网页“操作间隔”可设 **0–2000 毫秒**，修改并离开输入框后保存，下次启动沿用。此值是松键到下一次按键的最短间隔；画面核对会额外耗时。45 与 120 毫秒都完成过实机放置核对。修改等待中的任务也会生效；活动操作期间切走游戏仍会停止，大间隔可能导致旋入超时。

离线求解新增 SRS / SRS+ 选择和剩余 1–6 行收尾。只填当前块、实际可见的 Next 和 Hold；不知道的未来不要补入。说明包含一个“剩余三行、五块收尾”的实际案例，玩家可按求解结果手动操作。

默认启动等待空棋盘。打开恢复选项后可在 PC 断链时清场重新识别。七袋缺块推断属于搜索假设，实际 Next 到达后必须核对，不把猜测写入已观察块序。

## 随机策略的范围

第一段优先保留 I 的标准 PCO，无法这样构建时使用有限预览搜索；第二段重新规划四行 PC；第三段使用适合额外块的 DPC 结构及镜像，再求解收尾。已知的收尾路径会完整保留，未知未来只执行已观察到的第一步。

目前并非任意随机块序都能不断链。有限 Next 的选择以及 SRS 90°规则仍会造成无方案；ZEN 的 SRS+ 90°已接入；180°和高速 / 20G 尚未验证。程序会明确记录断链，不能把固定种子或资料中的成功率当成随机模式保证。

最新随机实机测试已连续完成 **两轮、70 块、6 次 PC、28 行**，未重开，记录在 `output/live-20261013-204322-74790576/session.json`；50 项自动检查通过；这份两轮记录使用 CUSTOM 标准 SRS，属于历史实机验证。

此前固定种子 1234 的十轮实机记录保留在 `output/live-20261013-193410-aed54225/session.json`，仅用作开发回归；正常启动入口不会使用它。最新随机测试记录见 `output/validation.json`。

## Blitz 得分程序

玩法策略新增“Blitz 得分”：按当前 .TTC 的绑定计算 SRS+ 路线；PC 搜索超时就消行续打。极限档无 PPS 节拍，支持 ARR=0 压墙和 180°，低重力优先空中短路线，高重力使用地面旋入。可直接打开 SOLO → BLITZ；CUSTOM 可下载完整曲线、固定 Level 10、Level 15 或 20G 的 .TTP。模拟条件选择本身不会修改游戏。

极限档连续三局不同随机原生 Blitz 均完整打完两分钟并到达 Level 15，无误落或重开。最高 **2,235,963 分、634 块、51 PC、252 行**；最快整局 **5.40 PPS**。后两局无落点修正，perfect pieces 约 86.7%，每块 faults 比旧版减少约 80–81%。详见 [高分策略与极限条件](docs/Blitz高分策略与极限条件.md)、[历史研究与实测](docs/Blitz研究与实测.md)，页面说明在 `/blitz-manual`。峰值不当作整局平均，尚未宣称总分最优。

```powershell
python scripts/run-blitz.py --profile blitz --seconds 120 --speed sprint
```

程序等待随机新局，不自行选择游戏模式；开发测试请使用 CUSTOM。

## 离线求解和回放

下方可以选择剩余 1–6 行收尾、五包 `4＋4＋6` 循环，或十袋七次纯四行循环。输入第一块（当前块）与后续块，用空格或 `|` 分包；可编辑初始棋盘，支持 Hold。

“载入已验证示例”会按所选目标填入块序。求解通过后，用进度条、上一块 / 下一块或自动回放检查每次落地和消行，也可以导出 JSON。完整循环按所选模式检查第 10、20、35 块，或第 10、20、30、40、50、60、70 块的全清。

## 日志和恢复现场

- `output/live-日期时间-编号/session.json`：实际核对过的步骤、循环数、PC 数和消行数。
- 同一目录的 `start.png`、`pc-*.png`、`stopped.png`：开始、每次 PC 和停止时的窗口截图。
- `output/fast-*/`：快速求解的地形、组件输出和验证回放。
- `output/loop-*/result.json`：完整五包循环的来源编号与回放。
- `output/environment.json`：客户端壳版本与窗口尺寸，不等于游戏内部规则版本。

程序在预测与实际不一致时会停止并保留现场。启动和取消不会修改 TETR.IO 的安装文件。

## 开发

Python 3.10+，依赖见 `requirements.txt`；本机 Codex 的运行环境已有 Pillow 和 NumPy。Windows 截图与键盘控制直接调用系统接口，支持高 DPI。

```powershell
python -m pc_lab serve --open
python -m pc_lab solve --queue 'JLOSTZI | JLO'
python scripts/run-live.py --cycles 1
python scripts/run-live.py --cycles 2 --auto-retry --max-retries 3
python -m unittest discover -s tests -v
```

`pc_lab/engine.py` 独立验证旋转、碰撞、单格 Hold、消行和路径。出生点已按实际截图校准为 `(4,21)`。执行时重新优化到同一落点的路线，优先空中旋转再直落，必要时才软降到底后旋入。选择 SRS+ 时，搜索与执行共同使用 data/srsplus90.properties；实时路径不使用半空单格软降。

`java/PcSearch.java` 使用 solution-finder 1.43 的搜索接口只找首个方案，避免旧 `path` 命令枚举全部十块布局耗尽内存。`scripts/build-bridge.ps1` 编译桥接组件；`scripts/setup.ps1` 下载便携 Java、求解器并编译组件。Java 下载会校验 SHA-256。旧的枚举适配器 `pc_lab/solver.py` 保留作验证比较，界面使用快速适配器。

`pc_lab/openers.py` 和 `data/dpc-setups.json` 包含来自用户指定资料的 PCO / DPC 结构及镜像；每一个结构仍经过独立可达路径检查。`pc_lab/online.py` 把预测与观测分开；`pc_lab/live.py` 负责实际按键与每步画面核对。
