# TETR.IO 规则核查与旋转策略

核查日期：2026-10-14。当前重点是本机 ZEN 无重力练习，另保留已配置 CUSTOM 的标准 SRS 支持。桌面 EXE 是客户端壳，壳版本不等于游戏规则版本。

## 查到的规则与证据

| 项目 | 依据 | 本项目处理 |
|---|---|---|
| DAS、ARR、DCD、SDF、Sonic Drop、S/Z 旋入 | [TETR.IO 官方 FAQ](https://tetrio.github.io/faq/mechanics.html) | 横移点按后松开；普通落点先转再降；插入时软降后松开再操作。 |
| SRS+ 与独立 180° | 官方 FAQ 的旋转参考及 [当前官网的按键说明](https://tetr.io/) | 建模 SRS+ 90°；不把 180°当成两个 90°，当前不发送 180°。 |
| I 踢墙顺序不同于 SRS | [官方仓库 issue 506](https://github.com/tetrio/issues/issues/506)，含成员发布表格及用户逐项比较 | 修正四组 90°转移中的 I 候选次序；保留“只取第一个合法踢墙”。 |
| kick table、7-bag、Hold、Next 数、lock delay / resets 可配置 | [客户端配置参考](https://github.com/lemoncove/tetrio-bot-docs/blob/master/Room_Config.md) | 实时默认 SRS+；标准 SRS 的 CUSTOM 需明确选择，ZEN 固定 SRS+。不假定所有模式具有相同锁定数值。 |
| 随机七袋 | [Piece RNG 参考实现](https://github.com/lemoncove/tetrio-bot-docs/blob/master/Piece_RNG.md)及历史窗口队列核对 | 只在袋边界已知、缺一成员时推断；其他隐藏块只作为假设。正常启动不读取种子。 |
| ZEN 五个 Next、灰色不可再用的 Hold、I 实际踢墙 | 本机截图与实际键盘输入 | 识别实际预览数量；灰色 Hold 不允许本块再次交换；未知变化立即停止。 |

Issue 506 是 2020 年资料，不是当前完整规则规范。2024 年 [issue 1382](https://github.com/tetrio/issues/issues/1382)的无截图 I 旋转报告被标为 cannot reproduce，不能作为推翻踢墙表的证据。官方补丁页正文由脚本加载，本次未取得完整最新规则差异；官网公开 HTML 的直接下载被拒绝，也没有通过客户端内部状态取得规则。关键故障结合本机实测确认；其他转移使用公开表格转换，尚未把所有转移逐一做当前实机测试。

## I 块故障的具体解释

原始记录：`output/live-20261013-233735-53c38fb6/movement-mismatch.json`。I 在 Z 上方横放，整数模型的位置为 `(x=1,y=5,朝向0)`。顺时针之后，旧标准 SRS 预测竖直 I 位于最左列；实际客户端把它踢到第 4 列。棋盘本身没有变化，因此不是消行、Next 错读或漏按。

在本项目的整数旋转中心表示中，I 的 0→R 第一候选是 `(1,0)`；它并不表示 Guideline 几何中心“无碰撞也踢一格”，而是四格形状与整数中心之间的转换。使用与 solution-finder 一致的形状定义后比较候选才有意义。

修正的四组为 `I.NE / I.EN / I.SE / I.WS`，其中 N/E/S/W 对应 0/R/2/L。相对于标准表交换第 2、3 个及第 4、5 个候选的优先顺序。完整用于搜索和执行的表位于 `data/srsplus90.properties`。故障的 0→R 转移已经与原始实际位置核对一致。

## 路线策略

1. 先保持求解器的目标四格不变，搜索出生高度上的横移和 90°旋转，再直接硬降到目标。
2. 有这种路线就采用它，省去接触堆积后的踢墙、锁定时间与识别等待。
3. 只有直接落不到目标时，搜索瞬降到接触面、横移或合法旋转后的插入路线。
4. Java 搜索、Python 碰撞验证和实机执行读取同一份旋转表。旋转遇到碰撞只采用首个合法候选，不能挑一个想要的候选。
5. 每次输入后观察实际四格；未移动才允许有限补发，移到其他位置立即停止；硬降前再次核对，硬降后比较锁定棋盘、Hold 和新块。
6. 用可设置的最短操作间隔控制节奏；大间隔不会修复错误规则，反而可能超过旋入锁定时间。

## 已经验证什么

- 故障地形回归：SRS+ 0→R 的预测与原始实机第 4 列吻合；最左目标能由空中逆时针、左四次、硬降到达。
- 当前实机左列 I：`output/native-i-left-verification.json`，设置 45 毫秒，四格实际落在第 1 列底部四行，无重开。
- 当前实机其他放置：120 毫秒间隔的 I 右列、T/J/S 等逐步核对记录保留于 `output/live-20261014-001732-2a42a8c6` 和 `output/live-20261014-002348-88e92892`；后一个因规划无收尾而停止，不能算 PC 成功。
- 真实随机 ZEN 第一轮的 35 个已核对落点：重新计算并离线回放 153 个动作，PC 位于 10、20、35；4 个步骤需要插入，其余可以直落。新版整轮按键尚未重新在实机执行。
- 五个 Next、灰色 Hold、两枚相邻 I 受蓝色鼠标光晕影响、橙色 ZEN 进度条遮住右边框，都有保存截图回归。

仍未完成：180°踢墙、所有 CUSTOM kick tables、有重力执行、任意随机序列的不断链保证。有限预览规划失败与旋转/识别异常分别记录；不会把重新开始后的成绩并入上一局。
