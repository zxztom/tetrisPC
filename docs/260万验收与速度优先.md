## 为什么要改变点按发送

中间 DAS 1.5F＋1ms 的首局在 162 块停止，没有进入第二局。第 163 块 Z 计划右移两次，第二次控制端实际保持约 82.16ms，超过 25ms DAS，实际落在右墙。保存未完成步骤与截图，没有补发或硬降，没有完整原生录像，不冒充正常局。

新成对点按用一次 SendInput 顺序提交按下、松开，避免 Python 在两个提交之间被延迟调度。不是跳过画面确认：相同物理键之间仍留中性帧，旋转中间下落仍核对，硬降前核对四格、之后核对整盘，失焦／F8／Esc 停止并释放。微软文档说明批量输入顺序插入且不被其他输入插队；它不保证游戏已经处理，因此仍需实机验证。

两局实际方向点按最长 6.67、10ms，未跨 25ms DAS。192 项完整检查通过；成对提交、失焦／停止零输入、部分接受后释放并停止有回归检查。资料：https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput

## 当前决策

保留所有旧策略；暂以 PC 为冲分基线，使用已实际应用并导出的配置与成对点按。finesse 仅作为输入开销的诊断，分数与真实 PPS 才是选择依据。可见收尾、额外 T-spin 或更短 DAS 必须另外验证，不因为名字或离线估分更漂亮就替换基线。所有失败及随机局分母保留，自动刷分只取单局最高值。

## 历史：0.12.10 的等价处理优化

DXGI 返回 BGRA 数据后，原代码先复制并转换整张 RGB，再缩到识别尺寸。新代码借用 Pillow 的只读缓冲区视图，先用相同 NEAREST 规则缩小，再复制和转 RGB；非连续数组用 Pillow 生成的采样索引。最终返回图像不引用会被下一次截图重用的缓冲区。多尺寸、比例、透明字节与非连续 ROI 的逐像素测试通过。

仅图像转换的交替顺序微基准：2200×1800 到 880×720，旧中位约 12.02ms，新约 3.50ms；3072×1920 到 1229×768，18.02ms 对 5.42ms。它不包含整个截图、识别或游戏，不把这个倍数称作整局提速。结果 `output/capture-image-0.12.10-benchmark.json`。

极限档另外去掉开始软降后的固定18ms等待，直接等实际四格已落地、棋盘和活动块/Hold身份一致才继续；其他速度档保留原等待。没有删除落点/整盘核对和连续旋转的中间下落屏障。完整200项检查通过，新加的真实T地形回归另通过；该版两局随后得到2,479,544 / 2,188,581，676 / 679原生块（各一个自然尾块），均Level16，审计通过。后续throughput的四局见本文最新验收。

同落点多一次短输入赚 T-spin 的 CLI 实验仍默认关闭：自己666块历史局的95个T地形中只多找到1个mini机会，不能证明划算，不将它列为当前推荐。该分析只读已经观察到的棋盘和目标，不使用种子或未来队列。
